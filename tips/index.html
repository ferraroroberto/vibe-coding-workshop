✅ Auto Approve

Stop babysitting every file edit. Let the LLM run.

❌ Without Auto-Approve

  • Confirm every file write
  • Confirm every shell command
  • Flow interrupted constantly
  • Premium requests wasted on confirmations

✅ With Auto-Approve

  • LLM executes in one pass
  • You review the result, not each step
  • Faster feedback loops
  • Deep flow state preserved

🗂️ Project Structure

Consistent structure = predictable LLM reasoning.

project/
├── src/ # main code
├── config/ # JSON configs
├── tests/ # pytest
├── tmp/ # scratch space
├── docs/ # markdown docs
├── agents/ # LLM prompts
└── .env # secrets (gitignored)
🎯 Use the same layout for all projects. The LLM will know where everything lives without being told.
🗑️ Use tmp/ for experiments so LLMs don't touch production files.

⏪ Reverting & Checkpoints

When the LLM loops, stop, revert, restart smarter.

🌀 The Loop Trap

  • LLM tries fix A → breaks B
  • Fixes B → breaks A again
  • You've wasted 10 prompts
  • Codebase is a mess

✅ Checkpoint Technique

  • Get the solution to work
  • Note the final state in markdown
  • Revert to the clean version
  • Restart using summary as prompt
git stash / git checkout <clean-commit>

🚫 Avoid Confirmation Prompts

Every unnecessary prompt costs money and time.

💸

The Problem

Some tools bill every prompt as a premium request — including "Should I proceed?"

⚡

The Fix

Write instructions so clear the LLM never needs to ask. Front-load all context.

❌ "Create the file. Ask me before writing."

✅ "Create src/etl.py with this logic. Use snake_case.
Write it directly without asking for confirmation."
📄 examples/10-avoid-confirmations.md

🏗️ Architecture Strategy

Know when to go monolith vs modular from day one.

🔬 Exploring

Start with a monolith. One file, all logic. Get it working first.


Once it works → ask LLM to split into modules.

📐 Architecture is Clear

Start directly with the final structure.


Define modules upfront. LLM fills in the implementation.

🎯 Iteration limits: set them high. Strong models handle long runs. Monitor, don't stop prematurely.
